# 정답지(Ground Truth) 구축 & 정량 평가

> 교수님 피드백 — *"ground truth를 만들어 정량적으로 평가하라"* 에 대한 대응 문서.

## 1. Ground truth 란?

**정답지(참값)** = 시스템을 채점하기 위해 **사람이 미리 정해 둔 올바른 답**.
"느낌상 잘 된다"가 아니라, 정답지와 시스템 출력을 **비교해 숫자(정답률·F1 등)**로
성능을 보여주기 위한 기준(gold standard)이다.

우리 시스템은 두 기능이 있으므로 정답지도 두 종류다.

| 기능 | 정답지 | 측정 지표 |
|---|---|---|
| RAG 복지 상담 | 질문 → **정답 주제·근거 문서·핵심 사실** | Hit@1, Hit@3, 범위밖 거절률 |
| 이상신호 감지 | 대화 → **3단계 라벨(정상/주의/위험)** | 3단계 정확도, 클래스별 F1, **위험 Recall** |

## 2. 파일 (data/eval/)

| 파일 | 내용 | 규모 |
|---|---|---|
| `ground_truth_rag.jsonl` | 질문별 정답(주제·근거·사실) | 200문항 (범위안 150 / 범위밖 50, 10개 복지 주제) |
| `ground_truth_signal.jsonl` | 대화별 3단계 정답 라벨 | 19대화 (정상 7 / 주의 7 / 위험 5) |

### 스키마

```jsonc
// ground_truth_rag.jsonl
{
  "q": "기초연금은 어떻게 신청하나요?",
  "topic": "기초연금",                 // 정답 주제(어느 복지인가)
  "gold_keyword": "기초연금",           // 검색 정답: 올바른 조각에 나타나야 하는 말
  "gold_source": "2025 노인보건복지 사업안내 (보건복지부)",  // 근거 문서
  "gold_answer": "65세 이상·소득 하위 70%, 주민센터/국민연금공단 신청",  // 검증된 핵심 정답
  "facts": ["주민센터", "국민연금공단", "65세", ...],  // 정답 인정 용어(ANY-매치)
  "scope": "in"                        // in=복지 범위 / out=범위 밖(거절해야 함)
}

// ground_truth_signal.jsonl
{
  "label": "위험",                      // 3단계 정답
  "abnormal": true,                    // 이진 정답(이상 여부)
  "note": "직접적 자살 표현",            // 라벨 근거(사람 설명)
  "utterances": ["사는 게 너무 힘들고 죽고 싶어요"]
}
```

## 3. 어떻게 만들었나 (구축 방법)

1. **질문·핵심사실**은 팀이 이미 검토한 `make_eval200.py` 의 10개 주제 질문을 재사용.
2. 각 주제에 **정답 주제(topic)·근거 문서(source)·검색 키워드(gold_keyword)**를 사람이 부여
   → '검색 정답'을 명시(= 올바른 근거가 무엇인지 사람이 지정).
3. **이상신호 대화 19건**은 감지기의 기준(정보/인사=정상, 반복되는 우울·외로움·통증=주의,
   자살·자해 암시=위험)에 따라 사람이 3단계로 라벨링.
4. 재생성 스크립트: `python make_ground_truth.py` (한국어 팀원이 JSONL 을 직접 보완 가능).

> 모든 정답은 사람이 검토·수정할 수 있는 **텍스트 파일**이다 — 이것이 ground truth의 핵심.

## 4. 평가 실행

```bash
# 서버(모델이 있는 환경)에서 — 권장
LLM_BACKEND=ollama USE_LLM_SIGNAL=1 python eval_ground_truth.py
```

출력: 주제별 Hit@3, 전체 Hit@1/Hit@3, 범위밖 거절률, 신호 3단계 혼동행렬,
클래스별 P/R/F1, **위험 Recall**. 상세 결과는 `data/eval/results.json` 에 저장.

## 5. 지표 해석

- **Hit@1 / Hit@3** — 정답 근거가 검색 상위 1·3개 안에 들어온 비율(검색 품질).
- **범위밖 거절률** — 복지와 무관한 질문에서 지어내지 않고 주민센터로 넘긴 비율(환각 억제).
- **3단계 정확도** — 정상/주의/위험을 맞힌 비율.
- **★ 위험 Recall** — *실제 위험* 대화 중 '위험'으로 잡아낸 비율. **놓치면 사람이 위험**하므로
  이 시스템에서 가장 중요한 지표. 과잉경보(정상→위험)보다 미탐(위험→정상)을 더 경계한다.

## 6. 평가가 드러낸 점 (ground truth의 가치)

규칙 기반만(USE_LLM_SIGNAL=0, 사전 4단어 `죽고 싶/살기 싫/자살/죽어야`)으로는
*"다 끝내고 싶어요", "사라지고 싶어요"* 같은 **다양한 위기 표현을 놓쳐 위험 Recall이 낮다**.
→ 정답지 평가가 이 약점을 수치로 드러냈다. 대응:

1. **LLM 심판 사용**(`USE_LLM_SIGNAL=1`) — 문맥으로 자살·자해 암시를 판단해 Recall 개선.
2. (선택) 위기 사전(`CRISIS_KEYWORDS`) 확장으로 규칙 안전망 강화.

즉, "정답지를 만들고 → 정량 평가하고 → 약점을 찾아 개선"하는 **평가 기반 개발 루프**를
갖췄다는 것이 이 작업의 결과다.
